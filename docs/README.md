# Docs

## Engine conventions

- Units are millimetres. Element `x`/`y` are relative to their band; `RenderedElement` positions are absolute on the page.
- Detail rows come from `IDataContext.GetRows(definition.DataSource)` and must be **pre-sorted** by the group expressions (outer group first). The engine does not sort.
- `ObjectDataContext` reads public properties, dictionary keys and `DataRow` columns (case-insensitive, dotted paths allowed, DBNull = null); it never calls methods. Row collections come from its `sources` or from a collection property of the root object.
- Field lookup order in expressions: variables (aggregates, `PageNumber`, `PageCount`) -> current row -> root context. Names are case-sensitive.
- Aggregates: `Count` counts non-null values, the rest need numbers, nulls are skipped. `group` = reset when that group starts; omitted = whole report.
- Page header/footer bands are evaluated after layout: they can use `PageNumber`, `PageCount`, root fields and report-wide aggregates, but not row fields.
- Bands are never split across pages. A group header (all its header bands) is kept with the first row's detail bands: if they do not fit in the space left, both move to the next page. Set `pageBreakBefore: true` on a group to start each of its instances on a new page (the first one never leaves an empty page).
- Element `align`: `left` (default), `center`, `right`, inside the element box (`x`..`x+width`).
- Element `type`: `text` (default), `line` (from `x,y` to `x+width,y+height`; use `height: 0` for a horizontal rule) or `rect` (outline). `thickness` is in mm (default 0.2).
- `wrap: true` on a text element wraps it to the element `width` (word wrap, long words break by character, `\n` is a paragraph break) and grows the band to fit. It needs an `ITextMeasurer`: pass `new PdfTextMeasurer(options)` (same `PdfRenderOptions` as the renderer) to `ReportEngine.Render`. Page header/footer bands never grow, and the keep-together check uses defined band heights, not grown ones.
- `columnHeader` bands (table column titles) are printed once after the report header on page 1 and again at the top of every following page, before the content. They can use root fields and aggregates' current values, not row fields; they honour `visible`. They differ from group header bands, which repeat per group, not per page. Their height is subtracted from the room available to the other bands.
- `underline` underlines a text element. `rotate` (0, 90 or 270) turns its content; 270 reads bottom to top. Rotated text is centred in the box and is not wrapped, so make the box long enough.
- `padding` (mm) on a text element insets the text on both sides inside the box (fill and border still cover the whole box); `wrap` uses the narrower width. It must be at least 0 and less than half the width.
- `page.columns` (default 1) and `page.columnGap` (mm): with more than one column the single `detail` band becomes a cell, repeated left to right and then top to bottom (labels). Cell width is `(page width - 2 * margin - gaps) / columns`; element `x` is relative to the cell. Other bands stay full width and start below a partly filled row. Several columns need exactly one detail band.
- `vAlign` (`top` default, `middle`, `bottom`) places text inside a taller box. `fitBand: true` stretches an element to the bottom of its band, so fill and border match a band that grew because another element wrapped (table rows).
- Font fallback: set `PdfRenderOptions.FallbackFontFilePath` (and optionally `FallbackBoldFontFilePath`) to draw characters the main font lacks with a second font, e.g. Arial (Vietnamese) as main and Malgun Gothic (Hangul) as fallback. The renderer reads each font's character table, splits text into runs and `PdfTextMeasurer` measures the same runs, so `wrap` stays accurate. It works only when ClioReport registers its own font resolver (not when you assign `GlobalFontSettings.FontResolver` yourself). Fallback italic is simulated.
- Colours: `color` (text, line and outline), `fill` (box background of text and rect elements) and `border` (outline around a text element, width = `thickness`), as `#RGB` or `#RRGGBB`. Anything else is a `ReportException`. Fill is drawn first, then the border, then the text, so cells of a table are a text element with `fill`/`border` per column.
- Text style: `bold`, `italic` (booleans) and `fontSize` (points, 0 = `PdfRenderOptions.FontSize`) on a text element. `wrap` measures with the same style. Without font files for the style, PDFsharp simulates bold/italic; set `PdfRenderOptions.BoldFontFilePath`, `ItalicFontFilePath` and `BoldItalicFontFilePath` for real faces. A custom `ITextMeasurer` can override `MeasureWidth(text, TextStyle)` and `GetLineHeight(TextStyle)`; their defaults ignore the style.
- Band `visible`: an expression evaluated where the band is emitted (row fields allowed for detail/group bands). A falsy result (false, 0, empty text, null) skips the band and its space. Page header/footer bands are evaluated like their elements (page variables and root fields only) and keep their reserved space when hidden.
- `type: "qrcode"`: QR code of the element's expression/text (UTF-8, error correction level M, version picked automatically; text too long for version 40 is a `ReportException`). Drawn as a square of side `min(width, height)`, positioned by `align`, with square modules. It does not add a quiet zone: leave at least 4 modules of blank space around it, and print at 20 mm or more for a short text.
- `type: "barcode"`: Code 128 of the element's expression/text, drawn as bars scaled to the element `width` (set C for digit-only text of 4+ even digits, set B for printable ASCII; anything else is a `ReportException`). Leave a quiet zone (about 10 modules of blank space) around it and keep the width at or above ~0.25 mm per module (`Code128.Encode(text).Length` gives the module count). It does not print the human-readable text: add a normal text element for that.
- `type: "image"`: the expression's value is the image. A `byte[]` (PNG, JPEG or BMP) is used directly; a string is a file path, which the PDF renderer only loads when `PdfRenderOptions.ImageRoot` is set and the path stays inside that folder. The image keeps its aspect ratio, fits inside the element box and follows `align`.
- `type: "table"`: a grid with its own columns, placed anywhere in a band. `columns` are `{ header, expression | text, width, align }` (width 0 = share the rest of the element `width`; widths must fit). Rows come from `source` (a collection, resolved with `GetRows` on the current row, so a detail band can show the child lines of its row, or on the report root elsewhere) or from fixed `rows` (cells are text, or an expression when they start with `=`). Style: `fill` is the header fill, `altFill` every second row, `border`, `thickness`, `padding`, `bold`, `italic`, `fontSize`, `color`, `rowHeight` (default 5 mm), `headerHeight`, `showHeader` (default true; header is bold), `wrap` (rows grow to their tallest cell; needs an `ITextMeasurer`). The table is as tall as its rows and grows its band; it cannot be split across pages, so for long data keep using `columnHeader` + `detail` bands. Total row: give a column `total` (`sum`, `count`, `avg`, `min` or `max`, over that column's expression for every row, nulls skipped) and, optionally, `totalFormat` (a .NET format such as `N0`); the table then ends with a bold row filled like the header, with `totalLabel` in its first column that has no total. Only for tables with a `source`.
- `type: "list"`: repeats the elements in `items` once per item of `source` (resolved like a table's). Item elements are positioned relative to the item's top-left corner and see the item's fields. `height` (or `itemHeight`) is the fixed height of one item, `across` items per row (default 1) and `gap` between items in mm; the element `width` is shared between the items of a row. The band grows to fit the list. Items can contain tables and other lists.
- Numbers print with invariant culture; use `Format(x, 'N0')` for thousands separators.
- `schema` (optional, written by the designer): `{ root: [{ name, type }], collections: [{ name, fields: [{ name, type }] }] }` with `type` `text`, `number` or `date`. It only feeds the designer's field lists; the engine ignores it.

## Importing .rdlc (`ClioReport.Rdlc`)

```csharp
var result = RdlcImporter.ImportFile("Report.rdlc");   // or Import(Stream) / ImportXml(string)
foreach (var w in result.Warnings) Console.WriteLine(w);
File.WriteAllText("report.json", ReportSerializer.Serialize(result.Definition));
```

- Imported: page size and margin, page header/footer, text boxes (value, font, bold/italic/underline, colours, fill, border, padding, alignment, `Format`), lines, rectangles, and one Tablix: header rows and column-hierarchy header cells (including spanning headers) -> `columnHeader`, row groups -> groups with header/footer bands, details row -> `detail`, other rows -> `reportFooter`. Items above the Tablix -> `reportHeader`, below -> `reportFooter`. `DataSetName` becomes `dataSource`.
- Expressions: `Fields!X.Value`, `Parameters!X.Value`, `Globals!PageNumber/TotalPages`, `&`, comparison and logic operators, `Sum/Count/Avg/Min/Max` (turned into `aggregates`, scoped to the named group), `IIf` (becomes `a ? b : c`), `First/Last(Fields!X.Value, "DataSet")` (becomes the plain field `X`: supply it as a root field), `UCase/LCase/Trim/Len/Round/Abs/Format`. Anything else (e.g. `Switch`, `Now()`) is skipped with a warning; the text box is left empty.
- Not imported (warned): images, charts, subreports, column groups, row-group header cells, several Tablix, conditional visibility, per-side borders (all sides are drawn), text with several styles inside one paragraph (first run's style wins; stacked paragraphs with different styles become separate elements), `CanGrow` (set `wrap` yourself and pass an `ITextMeasurer`).
- RDL 2005 `Table` is not read; open the file in Visual Studio and save it to upgrade it to Tablix.
- Always review the result: the importer reports what it knows it skipped, not whether the layout looks right.

## Designer (`src/ClioReport.Designer/wwwroot/index.html`)

A single HTML file, no build step and no dependencies: open it in Chrome or Edge. It edits the same JSON the engine reads.

- **Open / Save**: Chrome and Edge save back to the same file; other browsers download it. Reports are saved as `.clio` files (plain JSON inside; `.json` still opens). Drag a file onto the page to open it.
- **Canvas**: bands are drawn to scale (mm). Drag to move, handles to resize, drag a band's bottom edge for its height. Arrow keys nudge (Shift = 5 mm), Alt disables snapping, Ctrl+Z / Ctrl+Y undo and redo, Ctrl+D duplicates, Delete removes.
- **Panels**: left adds elements and bands (inserted in the usual order); right edits the selected element, band, or the report (page, groups, aggregates). `JSON...` shows and edits the raw file.
- `table` and `list` elements are in the left panel. A table shows its columns and two sample rows; edit columns and the data source on the right. A list draws one item with a ghost of the next: with the list (or an element inside it) selected, adding an element puts it into the item template.
- Drag an element icon from the left rail onto a band (or onto a `list`) to place it where you drop it. Shift/Ctrl+click or drag a box on empty band space to select several: they move, nudge, duplicate and delete together, and the right panel offers align, distribute, same size and shared style.
- Saving writes only non-default properties, so files stay small.
- **Import RDLC**: with the host running, *Import RDLC* converts a `.rdlc`/`.rdl` file into a report you can edit and lists what it could not convert. It does not need the host to be reachable from the internet and nothing is uploaded anywhere: the host runs on your machine.
- **PDF preview**: run `dotnet run --project src/ClioReport.Designer`, open http://localhost:5178 and press Preview. The host (localhost only) renders the report you are editing with `ClioReport.Pdf`. Without sample data every field is blank; load a JSON object via *Sample data...* (top-level arrays become row sources, a `data:image/png;base64,...` string is an image) to see real values. Unknown fields are then reported. Fonts come from the OS fonts folder (Arial, Malgun Gothic), as in the samples. Opening `index.html` as a file still edits, but cannot preview.
